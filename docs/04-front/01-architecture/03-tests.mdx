| Niveau | Outil | Ce qui est vérifié | Commande |
|---|---|---|---|
| Fonctions pures | Vitest | formatage, paramètres d'URL, tokens et contrastes | `pnpm --filter <package> test` |
| Composants | Vitest + Testing Library | ce que voit l'utilisateur : rôles et libellés accessibles, clavier | `pnpm --filter @clair/ui test` |
| Stories des composants | Storybook + Vitest (Chromium) + axe | chaque story s'affiche sans erreur ni violation d'accessibilité ; sa fonction `play` rejoue le comportement (clic, clavier, focus) | `pnpm --filter @clair/storybook test:stories` |
| Écrans | Vitest + fixtures | états chargement, vide, erreur, succès ; URL mise à jour par les filtres | `pnpm --filter @clair/screens test` |
| Stories des écrans | Storybook + Vitest (Chromium) + axe | chaque écran rendu sur ses fixtures, dans tous ses états, en mobile et en sombre, sans violation d'accessibilité ; `play` vérifie le titre et une interaction | `pnpm --filter @clair/storybook test:stories` |
| Parcours | Playwright + axe | site : chaque grande rubrique répond, a un titre de niveau 1, aucune erreur ni violation d'accessibilité grave ; documentation : pages de la section Front | `pnpm test:e2e --project=site` (ou `docs`) |

Règle : on teste ce que voit l'utilisateur (`getByRole`, libellés), pas les classes CSS.

## Stories des écrans

Chaque écran de `packages/screens` a sa story, `<Xxx>Screen.stories.tsx`, titrée `Écrans/…`. Elle reprend les fixtures fictives de son test. Le décorateur `withApi` de l'atelier (`apps/storybook/.storybook/preview.tsx`) lit les paramètres de la story et répond à la place de l'API, sans réseau :

```tsx
import { enErreur, jamais, parametresEcran } from "../story-utils.ts";

const navigate = fn();
parameters: parametresEcran("/groupes/assemblee/gex", routes, navigate),
// Chargement : { [chemin]: jamais }   Erreur : { [chemin]: enErreur(500, chemin) }
// play : await expect(navigate).toHaveBeenCalledWith("/groupes/assemblee/gex?initie=1");
```

Le test du catalogue (`packages/screens/src/catalogue.test.ts`) refuse un écran sans story `Defaut`, `Mobile` et `Sombre`, ni fonction `play`. Celui des composants (`packages/ui/src/catalogue.test.ts`) refuse un composant sans story `Defaut`.

## Couverture

`pnpm test:coverage` mesure la couverture de chaque paquet du front (Vitest et `@vitest/coverage-v8`), hors stories, tests et fixtures. Chaque paquet a son seuil dans son `vitest.config.ts`, juste sous le niveau mesuré : un changement qui fait baisser la couverture échoue, et le seuil se remonte quand la couverture monte. Le rapport HTML est écrit dans `packages/<paquet>/coverage/`, ignoré par git.

## Tests e2e du site

`e2e/site.fumee.spec.ts` vérifie le site construit (`pnpm --filter @clair/site build`), servi par `next start` sur le port 4310. Le site y parle à un **faux serveur d'API** (`e2e/fake-api.mjs`, port 4312) : listes vides, fiches en 404, aucune donnée parlementaire réelle ou inventée. Les requêtes vers l'extérieur (formulaire de don, photos des assemblées) sont coupées. Le job `e2e-site` de la CI les lance à chaque pull request ; il ne construit pas la documentation, dont le build télécharge la spécification OpenAPI de production.

Une nouvelle rubrique portée s'ajoute à la liste `RUBRIQUES` du test ; si son écran appelle une route que le faux serveur ne connaît pas encore, l'y ajouter avec la forme de réponse de `packages/data`.
