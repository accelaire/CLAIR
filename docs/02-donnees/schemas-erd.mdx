La base de données relationnelle de CLAIR (PostgreSQL 17) est structurée autour de **6 domaines métiers**. 

Pour faciliter la compréhension, chaque domaine dispose d'un schéma épuré mettant en valeur les clés de jointure (`PK`, `FK`) et la logique de rattachement.

---

Ce schéma résume les flux d'information principaux entre les grands domaines de la plateforme :

## 🏛️ 1. Élus, Mandats & Groupes Politiques

Modélise l'identité pérenne d'un parlementaire et son historique de sièges au fil des législatures (AN) ou mandatures (Sénat).

<Mermaid
  title="ERD : Parlementaires, Mandats et Groupes"
  chart={`erDiagram
    parlementaires ||--o{ mandats_parlementaires : "a pour sieges"
    parlementaires ||--o{ mandats : "occupe fonction"
    parlementaires ||--o{ parlementaires_identifiants : "anciennes chambres"
    groupes_politiques ||--o{ mandats_parlementaires : "affiliation"
    circonscriptions ||--o{ mandats_parlementaires : "territoire"

    parlementaires {
        uuid id PK
        string slug UK
        string nom
        string prenom
        string chambre
        boolean actif
        uuid groupe_id FK
    }

    mandats_parlementaires {
        uuid id PK
        uuid personne_id FK
        uuid groupe_id FK
        uuid circonscription_id FK
        int legislature
        int mandature
        date date_debut
        date date_fin
    }

    groupes_politiques {
        uuid id PK
        string slug
        string nom
        string nom_court
        string chambre
        int legislature
    }

    mandats {
        uuid id PK
        uuid parlementaire_id FK
        uuid commission_id FK
        string type_organe
        string qualite
    }
`}
/>

- **Séparation Personne / Mandat** : `parlementaires` contient la personne physique stable ; `mandats_parlementaires` isole chaque mandat (législature, circonscription, groupe d'époque).
- **Continuité inter-chambre** : `parlementaires_identifiants` conserve les anciens matricules (ex. `PA...` lors du passage de l'AN au Sénat).

## 📜 2. Dossiers Législatifs & Textes de Loi

Fédère le travail parlementaire des deux assemblées sous une même bannière thématique (`sujets`).

<Mermaid
  title="ERD : Sujets Transverses et Dossiers Législatifs"
  chart={`erDiagram
    sujets ||--o{ dossiers_legislatifs : "regroupe"
    sujets ||--o{ sujet_liens : "sources web"
    dossiers_legislatifs ||--o{ textes_articles : "compose"
    dossiers_legislatifs ||--o{ dossier_commissions : "examine par"
    commissions ||--o{ dossier_commissions : "saisie"

    sujets {
        uuid id PK
        string slug UK
        string label
        string status
        int dossier_count
    }

    dossiers_legislatifs {
        uuid id PK
        string uid UK
        uuid sujet_id FK
        string titre
        string etat
        int legislature
    }

    textes_articles {
        uuid id PK
        uuid dossier_id FK
        string texte_ref
        string numero
        string libelle
    }

    commissions {
        uuid id PK
        string uid UK
        string nom
        string type
        string chambre
    }
`}
/>

- **Sujets Transverses** : Un `sujet` associe le dossier de l'Assemblée et celui du Sénat portant sur la même loi pour donner une vision unifiée.
- **Articles & Versions** : `textes_articles` historise les rédactions successives des articles votés.

## 🗳️ 3. Scrutins, Votes & Amendements

Modélise le vote en séance publique et les positions individuelles nominatives de chaque élu.

- **Positions nominatives** : La table `votes` stocke chaque vote individuel (`pour`, `contre`, `abstention`, `absent`).
